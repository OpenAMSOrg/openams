Quick start  /  BoxTurtle, AFC Lite, OpenAMS

From kit to first load.

This page takes a built BoxTurtle on an AFC Lite board to its first load through OpenAMS. Most new units fail at bring-up, not at the printer: a switch wired backwards, a floating input, a motor turning the wrong way, two lanes swapped. Step 7 finds those before any filament reaches the toolhead.

1. What you need

  • A BoxTurtle with an AFC Lite board (STM32H723), wired as the AFC Lite manual shows.
  • Klipper and the klipper-mmu package on the printer's host (usually a Raspberry Pi).
  • OpenAMS installed with Klipper, with its buffer in the filament path.
  • Mainsail or Fluidd, to type commands into the console.

You build two firmware images, one after the other:

  • Safe image first. Reads every switch and the buffer. Refuses to move any motor.
  • Motion image second. Same wiring, allowed to move motors. Build it only after the safe image passes steps 5 and 6.

Each comes for USB or CAN; pick the one that matches how the board connects to the host.

2. Build

klipper-mmu is pinned to one Klipper version. Build in a separate Klipper checkout, not the one your printer runs:

git clone https://github.com/Klipper3d/klipper /path/to/klipper
cd /path/to/klipper
git checkout ce7002bedf37e938bb483572949f3703ac6476cb

From the klipper-mmu folder, add its build hooks and the small driver patch to that checkout:

python3 tools/install.py install /path/to/klipper
python3 tools/install.py install-driver-api /path/to/klipper

Start from the tested settings for this board, then build:

cd /path/to/klipper
cp /path/to/klipper-mmu/configs/boxturtle-h723-usb-safe.config boxturtle.config
make KCONFIG_CONFIG="$PWD/boxturtle.config" OUT=out-boxturtle/ olddefconfig
make KCONFIG_CONFIG="$PWD/boxturtle.config" OUT=out-boxturtle/ -j4

For CAN, use boxturtle-h723-can-safe.config. If your wiring differs from the AFC Lite layout, change pins, polarities and pulls under klipper-mmu › Device, board and lanes › Configure and reserve MMU pins:

make KCONFIG_CONFIG="$PWD/boxturtle.config" OUT=out-boxturtle/ menuconfig

For the motion image later, repeat this step with boxturtle-h723-usb.config (or -can).

3. Flash

Flash out-boxturtle/klipper.bin as you would any Klipper board: with DFU or Katapult, over USB or CAN. klipper-mmu has no flashing tool of its own.

4. Host

Install the host module into the Klipper your printer runs:

python3 tools/install.py install-host /path/to/real/klipper

Add the smallest section to printer.cfg. With the safe image, it only turns on the buffer probe that step 5 uses:

[klipper_mmu box]
mcu: mcu
diff_probe: True

box is the unit's name; every command here uses MMU=box. Later steps add:

  • step 5: diagnostic_startup and diff_calibration_file;
  • step 7: the openams_… options;
  • step 8: bowden_estimate_file;
  • step 10 (optional, recommended): path_reconciliation: True and driver_restart: True.

Restart Klipper after every change to printer.cfg.

5. Calibrate the buffer

The OpenAMS buffer reports its position as two analog signals. klipper-mmu turns them into one number: 0 relaxed, 1000 fully compressed. While printing it holds near 500; during a load, passing 700 means the filament has arrived. The unit will not finish starting up until the buffer is calibrated.

Flash the safe image, switch off motor power, and check the unit is connected (state=attached, connected=True):

KLIPPER_MMU_QUERY MMU=box
  1. Hold the buffer fully relaxed and read the sensor. Note a_raw and b_raw. 
    KLIPPER_MMU_DIFF_PROBE MMU=box
  2. Repeat at 2 to 8 positions in order, relaxed to fully compressed. Include both ends.
  3. Write the readings to a file such as ~/printer_data/config/box-diff-calibration.json, replacing each capitalised word: 
    {
  "channel_map": "a_low_b_high",
  "vref_mv": 3300,
  "min_valid_mv": LOWEST_GOOD_MV,
  "max_valid_mv": HIGHEST_GOOD_MV,
  "path_tolerance_counts": TOLERANCE,
  "points": [
    { "a_raw": A_RELAXED,  "b_raw": B_RELAXED,  "position_permille": 0 },
    { "a_raw": A_HALFWAY,  "b_raw": B_HALFWAY,  "position_permille": 500 },
    { "a_raw": A_SQUASHED, "b_raw": B_SQUASHED, "position_permille": 1000 }
  ]
}
  4. Reset the board. In printer.cfg, replace diff_probe: True with: 
    diagnostic_startup: True
diff_calibration_file: ~/printer_data/config/box-diff-calibration.json

The fields are explained on the Calibration page. Use your own readings: another buffer's numbers describe another magnet.

6. First boot check

KLIPPER_MMU_QUERY MMU=box
KLIPPER_MMU_SENSORS MMU=box
KLIPPER_MMU_DIAGNOSE MMU=box

The query should show startup_state=ready and startup_result=0. The sensor list shows every switch. If all is well, diagnose prints:

klipper_mmu box: no problems found; state=idle path_occupied=False hub=open

Anything else is a finding: which switch or condition, what it likely means, and what to change.

7. Commissioning

KLIPPER_MMU_COMMISSION checks the switches, the buffer and each lane, and says what to fix. Run the three checks in order. After a menu change, build, flash and run the check again.

Switches

Remove all filament, then:

KLIPPER_MMU_COMMISSION MMU=box STEP=switches
ReadingMeaningFix
openCorrect: nothing inserted.
madeReports filament when there is none.Remove leftover filament, or flip the switch's active level in the menu (like ! in printer.cfg).
unknownThe input is floating.Turn on its pull-up in the menu (like ^), or check the connector.

Buffer

Run this, then within about 10 seconds push the buffer fully in and release it:

KLIPPER_MMU_COMMISSION MMU=box STEP=fps
ComplaintLikely cause
Never movedBuffer cable or wiring, or a displaced magnet.
Did not reach 900Calibration is off, or the buffer lacks full travel.
Did not return near its startThe slide is sticking.
High before you touched itThe calibration is reversed. Calibrate again.

Each lane

This check moves filament, so build and flash the motion image first. Add to [klipper_mmu box]:

openams_motion: True
openams_idx: 1
openams_fps: fps0
openams_family: boxturtle
openams_bays: 4
openams_path_length_mm: 842.5
openams_host_watchdog_ms: 2000
openams_lease_max_age_ms: 1000

And for OpenAMS, anywhere in printer.cfg:

[fps fps0]
source_oams: klipper_mmu box
extruder: extruder

[oams_manager]

[filament_group T0]
group: box-0
[filament_group T1]
group: box-1
[filament_group T2]
group: box-2
[filament_group T3]
group: box-3
  • openams_host_watchdog_ms: the unit stops everything after 2 s without hearing from Klipper. Keep openams_lease_max_age_ms below it.
  • openams_path_length_mm is a placeholder until step 8 measures your tube.
  • The filament_group sections map tools T0–T3 to lanes 0–3.

Restart Klipper, then check each lane n from 0 to 3. You have 60 seconds to push filament in until its BAY switch clicks:

KLIPPER_MMU_COMMISSION MMU=box STEP=lane LANE=n
What happensWhat it means
A different lane's switch clicks firstThose two lanes are swapped on the board. Nothing moves.
The preload failsThe feeder turns the wrong way, does not grip, or the lane's LOAD switch is faulty.
The preload worksThe unit ejects the filament and asks whether the spool wound it back. Answer with ANSWER=yes or ANSWER=no.

A spool that does not wind back usually has a respooler motor turning the wrong way, or slipping.

8. Measure the Bowden tube

LOAD is refused until the tube from the hub to the extruder has been measured. Add a file to keep the result, and restart Klipper:

bowden_estimate_file: ~/printer_data/config/box-bowden.json

With nothing past the hub, measure using any loaded lane:

KLIPPER_MMU_CALIBRATE MMU=box BAY=n

The unit feeds that lane past the hub at crawl speed until the buffer sees arrival, and reports the length in millimetres. Put it in openams_path_length_mm. The path is shared, so one lane calibrates all of them. The result is used immediately and restored at every restart.

After that, a load must arrive within ±50 mm of the measured length. Much earlier means an obstruction; much later means slipping or a loose tube. Either way the load stops and says which. Measure again after changing the tube, recalibrating the buffer or updating the firmware.

9. First load

OAMSM_LOAD_TO_TOOLHEAD GROUP=T0

The unit speeds up toward 200 mm/s, slows to a 20 mm/s crawl before the toolhead, and stops when the buffer sees arrival. A load gets up to three attempts within 240 s. Afterwards the log has one line per attempt:

klipper_mmu box: lane 2 LOAD failed after 3 attempts
attempt 1, HUB to extruder: compressed at 312 mm past HUB (19% of the 1612 mm Bowden estimate), before the calibrated minimum: obstruction or kink in the Bowden, or a path shorter than calibrated (recalibrate); retract behind the HUB and retry
attempt 2, lane to HUB: no HUB after 523 mm: tip catching at the hub entry, spool snag, tangle or filament not gripped; back off and retry at half speed
attempt 3, HUB to extruder: no resistance within 1900 mm past HUB (118% of the 1612 mm Bowden estimate): lane drive slipping, PTFE disconnected between HUB and toolhead, FPS not responding (magnet, Hall or DiffA/DiffB wiring), or a path longer than the bound (recalibrate with KLIPPER_MMU_CALIBRATE)

A first-try success is only logged. A retried or failed load also prints to the console.

10. When something goes wrong

On a fault the unit stops everything and waits. Recover in this order:

  1. KLIPPER_MMU_DIAGNOSE MMU=box: what happened. It never moves anything.
  2. KLIPPER_MMU_ACK_FAULT MMU=box: acknowledge the fault.
  3. If a driver failed, fix the cause (motor power, cable), then KLIPPER_MMU_RESTART_DRIVER MMU=box LANE=n.
  4. Tell it where the filament is: KLIPPER_MMU_RECONCILE_PATH MMU=box ACTION=CLEAR if the shared tube is empty, or ACTION=ADOPT LANE=n if lane n is still in it.
  5. KLIPPER_MMU_RECOVER_SESSION MMU=box: start a clean connection.

Step 4 also clears OpenAMS's record of the fault (OpenAMS lane cleared). When things go wrong has the symptom table.

11. Before you trust it

Not tested on real hardware

BoxTurtle is finished in software and passes a whole-system simulation running the real firmware. It has not been tested on a real BoxTurtle. The motion settings are starting points from the AFC reference design, not measurements of your machine. Watch your first loads.

The defaults you built with. The gearing is 200 steps per turn, 16 microsteps, a 50:10 gearbox and 22 mm per output turn: 727.27 microsteps per millimetre.
