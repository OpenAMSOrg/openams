# STM32H723 Klipper-MMU Board Startup Contract

## 1. Scope & Execution Boundary
`board_startup.{c,h}` provides the bounded MCU board startup lifecycle for Klipper-MMU on STM32H723.
- **Task Context Requirement**: Invoked strictly from task context with interrupts enabled (`irq_save() == 0`). `board_startup.c` itself registers no `DECL_INIT` and no command. The legacy switched-buffer BoxTurtle AFC Lite image adds `boxturtle_boot.c`, whose init hook only wakes a task. The analog or hosted-diagnostic image excludes that early boot hook; hosted startup begins only after Klipper configuration and, for DiffA/DiffB, calibration delivery.
- **Safety**: Startup initializes outputs inactive regardless of the build flag. `ACTUATION=0` is the default; the separate experimental opt-in can publish 1 only through diagnostic startup readiness. This file still registers no commands and no automatic hook. STEP stays inactive (polarity from stepdir config) and PWM duty stays zero.
- **Blocking Characteristics**: Startup remains synchronous polling with interrupts enabled. It is not fully nonblocking and it is not measured electrical qualification. UART activation still advances cooperatively. ADC start uses bounded `gpio_adc_setup_local_pair_timeout` waits for regulator, calibration, and ready. Ordinary legacy ADC setup APIs are unchanged.
- **Allocation-Free**: Static data structures only; no dynamic allocation or private structure copies.

## 2. Lifecycle States
1. **`KM_BOARD_STARTUP_UNINITIALIZED` (0)**: Initial boot state. No peripheral mutation has occurred, and no local GPIO batch has been retained.
2. **`KM_BOARD_STARTUP_WAITING` (1)**: Physical setup complete; asynchronous TMC UART current confirmation pending.
3. **`KM_BOARD_STARTUP_READY` (2)**: All lanes confirmed; drivers bound; controller attached; core published.
4. **`KM_BOARD_STARTUP_FAULTED` (3)**: Failure or shutdown latched permanently until hardware MCU reset.

## 3. Physical Mutation & Safe-Off Invariants
- **Validation Before Mutation**: Arguments, clock readiness (`KM_CLOCK_STATE_READY`), and saved factories, including `km_config_h723_resources`, run before GPIO reservation or peripheral setup. With `CONFIG_WANT_GPIO_LOCAL`, `NULL` and count 0 is configured admission and skips only external-list validation and fieldwise inclusion. A non-NULL pointer with count 0, `NULL` with a nonzero count, or a count above `KM_RESOURCE_MAX_CLAIMS` is `KM_ERR_INVALID_PARAM`. A supplied array keeps `km_resource_plan_validate` and fieldwise inclusion, with the same failure precedence. With GPIO local off, `NULL`, 0 stays `KM_ERR_INVALID_PARAM` and the caller supplies and enforces complete external ownership. Rejection in this phase does not reserve pins, latch a fault, or touch outputs. These functions do not discover clients or run host checks. Trusted Klipper configuration checks `RESERVE_PINS` (MMU pins, transport, crystal), aliases, and `BUS_PINS` before deployment. Shared GPIO, ADC, and PWM registries cover participating driver APIs; direct MMIO is outside that guarantee. Startup does not attach commands. The switched BoxTurtle build may use the separate boot task; the analog/hosted build uses the diagnostic task after host init.
- **Conditional MMU pin batch**: When `WANT_GPIO_LOCAL` is enabled, this explicitly called API reserves exactly the validated expected-plan `KM_RESOURCE_PIN` entries once with `gpio_local_reserve`, after core init and before switch, ADC, feeder, or PWM setup. The call is all-or-none, preserves full pin width, and does not reserve external complete-plan entries or non-PIN timer/ADC claims. Those stay with their existing owners. `gpio_local_reserve` performs no clocks or MMIO. Invalid, busy, and shutdown become `KM_ERR_INVALID_PARAM`, `KM_ERR_CONFLICT`, and `KM_ERR_FAULTED`. A reject before success does not latch, claim components, or release anything; pins already reserved by someone else are a conflict. After success the claims persist until reset and are never released, including when later startup fails. Reservation time counts against `timeout_us`; shutdown, clock, and deadline are rechecked before component setup, and that failure latches with the pins retained and without foreign component cleanup. After pin reservation and switch setup, ADC start receives the fresh remaining original deadline. The board checks that deadline again after the reader returns. The reserve batch only covers expected-plan MMU digital pins. With `WANT_GPIO_LOCAL` off, the caller still owes GPIO ownership. Hardware qualification is absent.
- **Partial Setup Safe-Off**: Potential physical mutation is tracked prior to checking return values. If feeder setup, ADC start, switch setup, PWM setup, or controller attach fails after entry, raw clock-free shutdown paths disable all touched peripherals. Feeder setup can claim UART before returning an error, so fault cleanup shuts down touched TMC UART after STEP/DIR safe-off; repeated cleanup does not repeat that shutdown. Its task stops when latched, while a pending timer exits at its next callback. Reservation alone is not hardware activity. First switch GPIO returning pure `KM_ERR_BUSY` is a preexisting foreign binding: with no retained batch it performs no I/O, no cleanup, and no latching; after a successful batch the board latches failure, keeps the pins, and does not call switch shutdown on that binding.
- **IRQ-Protected Publication**: Final clock observation, shutdown/latch evaluation, and transition to `READY` share a single atomic critical section under `irq_save()`. An intervening interrupt exceeding `timeout_us` expires with `KM_ERR_TIMEOUT` and never publishes core.
- **Controller Shutdown**: Direct `km_controller_shutdown()` latches its internal callback; it does not remove its scheduler timer.
- **Permanent Latch**: Board fault and emergency cleanup remain latched across upstream `sched_clear_shutdown()`.

## 4. Hardware Realities & Genuine Remaining Gaps
1. **PWM Route Validation**: Shared `gpio_pwm_pair_validate_pins` checks supported timers and channel aliases with the same driver routine used by actual setup, without clocks, registers, IRQs, or claims. `km_config_h723_resources` calls it for every powered rewind pair before adding claims. Route lookup and this pure validation do not prove runtime resource availability or physical electrical/timing suitability. Paired ordinary PWM is still not complementary PWM.
2. **UART Receiver Pull-up**: Single-wire TMC UART receive pull-up is wired from saved per-lane configuration (`KLIPPER_MMU_TMC_UART_PULLUP`); physical bus pull-up and wiring requirements remain external hardware constraints.
3. **ADC Unit Ownership**: Startup may start the sequential paired reader by passing the fresh remaining original deadline to `km_adc_start`. The accepted shared ADC API already excludes ordinary and local unit sharing. Regulator, calibration, and ready waits on that start are bounded. A global external census is not implemented.
4. **Boot Identity & Host Attachment**: Verified boot identity, default-off diagnostic MCU orchestration, and host opt-in are integrated. See the ADC acceptance record. `board_startup` alone still registers no commands and no automatic hook. The separate diagnostic path uses the verified identity and initially attaches with START permission false. Opt-in measured DiffA/DiffB calibration delivery exists, but no real calibration has qualified the reference hardware. Full OpenAMS lifecycle, recovery, and hardware qualification are unfinished.
