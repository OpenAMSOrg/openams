# Composed FPS arrival checks

`make -C tests/klipper_board_startup test-fps-composed IMAGE_AUTOCONF=<saved H723 Diff actuation image autoconf.h>` builds two native variants over the saved image header: FPS with a configured toolhead switch and FPS without one. The fixture overlays measured-like test values for threshold, distinct samples, hold duration and travel bounds; these are test inputs, not recommended printer settings.

The FPS variants link production `mcu/config.c`, `pin_config.c`, `switch_config.c`, `switch_gpio.c`, `sensors.c`, `adc.c`, `board_startup.c`, `commands.c`, and `controller.c`, along with the operation core and trajectory sources. Klipper's GPIO/ADC reads are replaced by deterministic fixture inputs. Its scheduler shim keeps the ADC reader, diagnostic startup and controller timers registered independently, rejects duplicate timer registration, and runs due timers in deadline order. The operation itself is started through the registered command handler.

The cases cover sustained calibrated arrival after HUB and minimum travel; successful arrival with a fresh toolhead signal; refusal when the configured toolhead remains clear; successful FPS arrival with no toolhead configured while asserting that no toolhead presence is fabricated; an electrically invalid ADC pair; and reaching the maximum travel without arrival. Every case first delivers a calibrated HUB-to-arrival distance through `config_km_fps_steps` (LOAD is refused without one); the maximum-travel case calibrates to a short distance and checks that its arrival window stopped the feed with no compression. Startup and buffer processing use production composition and the real controller callback in these cases.

The release matrix runs it against its freshly built `boxturtle-h723-usb` actuation image, which uses FPS arrival without a toolhead switch; the toolhead variant overlays one. The cases start LOAD, so they are compiled only with actuation permission. The matrix also runs the ordinary Diff startup check over both USB image headers with no overlay. With `boxturtle-h723-usb-safe`, production startup validates the saved FPS defaults and START is refused. With `boxturtle-h723-usb`, LOAD feeds past the image's own minimum travel after HUB and completes when the buffer position is held above the threshold, then runs FOLLOW and UNLOAD. The switch-driven host join test uses `shim/switch_arrival_autoconf.h` to restore toolhead-switch arrival over the actuation header; its `MODE=fps` run joins the host to that header as built, with no overlay.

This is bounded native software validation. The supplied saved `autoconf.h` provides the board/transport build settings while the fixture header selects FPS test values for the executable; it is not exact dictionary qualification. It does not validate analog calibration on hardware, physical travel distances, sensor noise, or timing margins.
