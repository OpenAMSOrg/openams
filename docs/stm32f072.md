# The STM32F072 OpenAMS mainboard, and moving from klipper_openams

This page is for owners of the original OpenAMS **STM32F072 replacement
mainboard** (AMS 1 mechanics, OpenAMS mainboard firmware 2.0.x, connected over
CAN) who are coming from the separate `klipper_openams` repository. The board
keeps working unchanged: OpenAMS speaks the same wire protocol (the "legacy"
mode, [C1 section 1.4](contracts/C1_firmware_host.md#14-the-stm32f072-replacement-mainboard-legacy-protocol)),
and a working `klipper_openams` config loads as it is. What changes is listed
below. You do not need to reflash the board.

## What the host does for this board

- **Family and identity.** The board is recognized from its firmware dictionary
  (`MCU="oams-stm32f072rbt6"`), so `device_kind: auto` resolves to `ams1`, and
  the unit's status reports `identity.board: "oams-stm32f072"`.
- **Capabilities.** Motion, follower and PTFE calibration work as on any AMS 1,
  and `OAMS_CALIBRATE_HUB_HES` is available (other units refuse it). The
  board has no dryer or heater, and the host reports none.
- **Serial.** The firmware has no identity query. The unit's serial (shown on
  touchscreens, and in `devices.<unit>.identity.serial`) is the `canbus_uuid`
  of its `[mcu ...]` section. With no `canbus_uuid` it stays empty. The
  missing query is logged once at info level.
- **Environment.** The firmware has no environment query. Temperature and
  humidity come from the host `[temperature_sensor ...]` with
  `sensor_type: HDC1080`, and appear in the status as `environment` with
  `source: "hdc1080"`. The sensor is chosen with the new `[oams]` option
  `environment_sensor` (see below); with one HDC1080 sensor configured, nothing
  needs to be set.

## Config differences, key by key

Compared with `klipper_openams` master (`oams_sample.cfg` and the options
`src/oams.py`, `fps.py`, `filament_group.py`, `oams_manager.py`, `mfrc522.py`
and `hdc1080.py` read). **No key was removed, and no key changed its meaning,
its default or its unit.** Everything below is new and optional unless stated.

### `[oams NAME]`

| Key | Status | Notes |
|---|---|---|
| `mcu`, `oams_idx`, `fps_upper_threshold`, `fps_lower_threshold`, `fps_is_reversed`, `f1s_hes_on`, `f1s_hes_is_above`, `hub_hes_on`, `hub_hes_is_above`, `ptfe_length`, `current_target`, `current_kp`, `current_ki`, `current_kd`, `kp`, `ki`, `kd`, `fps_target` | unchanged | Same names, same defaults and ranges. Keep them as they are. |
| `environment_sensor` | new | The printer object that supplies this unit's temperature and humidity. Give the sensor's name from `[temperature_sensor NAME]` (for example `oams`); the full object name (`aht3x oams`, `hdc1080 oams`, `temperature_sensor oams`) also works. Optional: with exactly one HDC1080 sensor it is found on its own. With several sensors and no option, the unit shows no environment (one warning is logged). |
| `device_kind` | new | `auto` (default), `ams1`, `ams_ht`, `ams2`. Leave it on `auto` or set `ams1` for this board. |
| `fps` | new | Which `[fps]` lane the unit feeds. Optional with one `[fps]`; required when you name several. |
| `ptfe_length_0` to `ptfe_length_3` | new | Per-bay PTFE length overrides. Without them every bay uses `ptfe_length`, as before. |
| `spool_id_N`, `link_source_N` | new, host-written | Spoolman bay links. OpenAMS writes them itself; do not add them by hand. |

### `[fps]`

| Key | Status | Notes |
|---|---|---|
| `pin`, `reversed`, `sample_count`, `sample_time`, `report_time` | unchanged | `pin` is now optional only when `source_oams` is given; a board-mounted FPS keeps `pin`. |
| `max_speed`, `accel`, `set_point`, `use_kalico` | accepted | Parsed for compatibility and ignored, as before. `use_kalico` is no longer needed: the ADC interface is detected from the running Klipper. |
| `source_oams` | new | Reads the lane's pressure from a unit instead of a local pin. Exactly one of `pin` and `source_oams` must be set. |
| `extruder` | new | The extruder this lane feeds (default `extruder`). |

### `[filament_group NAME]`

`group` is unchanged (`oams1-0, oams1-1, ...`). It may now be empty or omitted,
so a group can be created and filled at run time (`OAMSM_CREATE_GROUP`,
`OAMSM_ASSIGN_BAY`). A duplicate group name is still a startup error.

### `[oams_manager]`

The section can stay empty. `reload_before_toolhead_distance` is unchanged. New
optional keys:

| Key | Default | Meaning |
|---|---|---|
| `monitor_interval` | 1.0 | Runout and health monitor period, seconds. |
| `positioning_wait` | 10 | Seconds a load waits for a freshly inserted spool to finish positioning; 0 disables the wait. |
| `toolhead_load_macro`, `toolhead_unload_macro` | `LOAD_FILAMENT`, `UNLOAD_FILAMENT` | Extruder-only macros `OAMSM_LOAD_TO_TOOLHEAD` and `OAMSM_UNLOAD_FROM_TOOLHEAD` call; a touchscreen runs the full toolchange (`OPENAMS_LOAD`, `OPENAMS_UNLOAD`) instead. The unload macro must heat and eject past the extruder gears (about 100 mm); see `_OAMS_TOOLHEAD_EJECT` in `oams_macros.cfg`. |
| `openams_config_path` | `oams.cfg` beside `printer.cfg` | The file OpenAMS writes group edits, calibration results and Spoolman links back into. **Set it if your `[oams]` and `[filament_group]` sections are not in a file named `oams.cfg`.** |
| `read_tag_on_insertion`, `read_tags_at_startup`, `auto_reload_on_runout`, `auto_create_spoolman_spools`, `apply_pa_on_load`, `sync_unit_tray_info` | true, true, true, true, false, true | Policy switches, also changeable at run time with `OAMSM_SET_OPTION`. |

### `[hdc1080]` and the sensor

The bare `[hdc1080]` section and the `[temperature_sensor NAME]` with
`sensor_type: HDC1080` (and `i2c_address`, `i2c_mcu`, `i2c_bus`, `i2c_speed`,
`temp_offset`, `humidity_offset`, `temp_resolution`, `humidity_resolution`) are
unchanged. The driver behind them is more robust: a sensor that stops
answering holds its last good reading for a few cycles and then reports 0.0
instead of a frozen value (the environment then shows nothing), and the
software reset now really resets the chip. Two options the sample does not
show, `simulate_supported_sensor_mainsail` (default true: the sensor appears as
an `aht3x` object, which Mainsail draws natively) and `HDC1080_report_time`,
behave as before.

### `[mfrc522 NAME]` and `[bambu_lab_tag_processor]`

Unchanged (`oams`, `cs_pin_a/b`, `reset_pin_a/b`, `spi_software_*`,
`spi_speed`, `key`, `key_b`, `read_block`, `poll_interval`, and the Bambu
master `key`). One new option: `bays_a` / `bays_b` (defaults `0,1` and `2,3`),
which bays each reader covers. The sample still says the readers need mainboard
firmware 2.0.25 or newer.

### Macros (`oams_macros.cfg`)

All `klipper_openams` macros are kept. Copy the new `oams_macros.cfg` (the
installer does) and add these optional lines to `[gcode_macro
_oams_macro_variables]` if you want to change them; the macros use the values
shown when a line is missing: `variable_unload_speed: 1000`,
`variable_extrusion_unload_additional_length: 250`,
`variable_additional_unload_speed: 5000`,
`variable_minimum_extrude_temperature: 0`. New helper macros (`_OAMS_ABORT`,
`_OAMS_FINISH_TOOLCHANGE` and similar) support the touchscreen and the optional
`gco-routines` toolchange. `oams_macros_ordered.cfg` needs `[gco_routines]`;
do not include it otherwise.

## G-code commands

Every `klipper_openams` command is still there with the same arguments:
`OAMS_LOAD_SPOOL`, `OAMS_UNLOAD_SPOOL`, `OAMS_FOLLOWER`,
`OAMS_CALIBRATE_PTFE_LENGTH`, `OAMS_CALIBRATE_HUB_HES`, `OAMS_PID_AUTOTUNE`,
`OAMS_PID_SET`, `OAMS_CURRENT_PID_SET`, `OAMSM_LOAD_FILAMENT`,
`OAMSM_UNLOAD_FILAMENT`, `OAMSM_FOLLOWER`, `OAMSM_CURRENT_LOADED_GROUP`,
`OAMSM_CLEAR_ERRORS`, `OAMSM_LOAD_FILAMENT_CANCEL`, `OAMSM_VALIDATE_LOAD`,
`OAMSM_RFID_READ` and `MFRC522_QUERY`. New commands (`OAMSM_SELFTEST`,
`OAMSM_LOAD_TO_TOOLHEAD`, `OAMSM_UNLOAD_FROM_TOOLHEAD`, group editing,
`OPENAMS_LOAD` with a slot id, and others) are described in
[C3](contracts/C3_commands.md). The dryer commands exist but refuse on this
board, which has no dryer.

## What to change in a working klipper_openams config

1. Nothing is required for the board to run. Install OpenAMS with
   `install.sh` (it moves the `[update_manager openams]` section from the old
   repository and replaces the old symlinks).
2. Optional but recommended: add `environment_sensor: oams` to `[oams oams1]`
   (the name after `temperature_sensor`), especially if you use more than one
   HDC1080.
3. If your `[oams]` sections are not in `oams.cfg`, set `openams_config_path`
   under `[oams_manager]`, or group edits and calibration writeback will go to
   the wrong file.
4. Drop `use_kalico` from `[fps]` if you like; it does nothing.
5. Check the FPS orientation once, after a load: the host reads the buffer
   through the `[fps]` pin and reports `fps.fps_value`, while the unit reports
   its own `fps_value` for the same buffer. If the two are inverses (0.21
   against 0.82, adding up to about 1), set `reversed: true` in `[fps]`, or
   remove it if it is already set. Nothing else breaks, because the firmware
   loads from its own value, but every UI draws the pressure bar the wrong
   way. The manager warns on the console once it has seen ten such samples on
   an idle loaded lane.
6. Refresh `oams_macros.cfg` from this repository and keep your own
   `_oams_macro_variables` values.

## What to check on a real board

- `OAMSM_SELFTEST` (read-only) lists the unit and reports no refusal.
- The unit's status shows `identity.board` `oams-stm32f072` and
  `identity.serial` equal to your `canbus_uuid`; `klippy.log` has one info line
  about the missing identity query and no traceback.
- `environment` shows a plausible temperature and humidity, and follows the
  sensor chosen by `environment_sensor`.
- `OAMS_CALIBRATE_HUB_HES OAMS=1 SPOOL=0` returns a threshold on a bay with
  filament, and is listed in the unit's supported actions.
- A load, unload and runout reload behave as they did under `klipper_openams`.
